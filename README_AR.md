# Backup Sentinel — الدليل العربي

**Backup Sentinel** أداة سطر أوامر محلية مكتوبة ببايثون لإنشاء لقطات احتياطية زمنية للمجلدات، والتحقق منها باستخدام SHA-256، وعرض النسخ المحفوظة، ثم استعادة البيانات بعد اجتياز فحص السلامة.

> الإصدار الحالي: **1.0.0** · يتطلب **Python 3.10+** · الترخيص **MIT**

## لماذا هذا المشروع؟

الفكرة الأساسية هي أن تكون عملية النسخ الاحتياطي واضحة وقابلة للتدقيق:

- كل عملية نسخ تنشئ لقطة جديدة مستقلة.
- تُحسب بصمة SHA-256 للملفات أثناء فحص المصدر.
- يُعاد التحقق من كل ملف بعد نسخه إلى اللقطة.
- يمكن فحص أي لقطة محفوظة لاحقًا.
- تُرفض استعادة اللقطة إذا فشلت في التحقق.
- تُحمى الملفات الموجودة في وجهة الاستعادة افتراضيًا.
- لا يحتاج البرنامج إلى حساب أو اتصال شبكي أو خدمة سحابية.

## الأوامر

### إنشاء لقطة

</div>

```bash
backup-sentinel create ./important ./my-backups
```

<div dir="rtl">

الملفات المخفية مستبعدة افتراضيًا. لتضمينها:

</div>

```bash
backup-sentinel create ./important ./my-backups --include-hidden
```

<div dir="rtl">

### عرض اللقطات

</div>

```bash
backup-sentinel list ./my-backups
```

<div dir="rtl">

تظهر النتائج بصيغة JSON، ويمكن أخذ قيمة `snapshot_id` واستخدامها في التحقق أو الاستعادة.

### فحص السلامة

</div>

```bash
backup-sentinel verify ./my-backups 20260920T100000.000000Z
```

<div dir="rtl">

تتضمن النتيجة حالة `ok` وقوائم الملفات `missing` و`changed`. إذا فشل التحقق يُرجع أمر CLI حالة خروج غير صفرية.

### الاستعادة

</div>

```bash
backup-sentinel restore ./my-backups 20260920T100000.000000Z ./restored
```

<div dir="rtl">

إذا كانت هناك ملفات موجودة مسبقًا في الوجهة، ترفض الأداة الاستبدال تلقائيًا. لا تستخدم `--overwrite` إلا عندما يكون الاستبدال مقصودًا.

## واجهة Python

</div>

```python
from pathlib import Path
from backup_sentinel import create_snapshot, verify_snapshot

manifest = create_snapshot(Path("important"), Path("backups"))
status = verify_snapshot(Path("backups"), manifest["snapshot_id"])

assert status["ok"]
```

## بنية اللقطة

</div>

```text
my-backups/
└── snapshots/
    └── <snapshot-id>/
        ├── manifest.json
        └── data/
            └── ... original relative paths ...
```

<div dir="rtl">

صيغة البيان الحالية هي الإصدار 1. ولكل ملف يُحفظ المسار النسبي والحجم بالبايت وبصمة SHA-256، إضافة إلى معلومات اللقطة نفسها.

## قواعد الأمان الحالية

1. لا يمكن أن يتداخل مجلد المصدر مع مستودع النسخ الاحتياطية.
2. لا تتبع الأداة الروابط الرمزية.
3. يجب أن تطابق بصمة الملف المنسوخ البصمة المحسوبة من المصدر.
4. يُكتب `manifest.json` بطريقة ذرّية باستخدام ملف مؤقت ثم الاستبدال.
5. لا تبدأ الاستعادة قبل اجتياز اللقطة كاملةً لفحص السلامة.
6. تُرفض الكتابة فوق الملفات الموجودة إلا عند طلب `--overwrite` صراحة.
7. أثناء الاستعادة، يُنسخ كل ملف إلى ملف مؤقت، ثم يُفحص، ثم يُنقل إلى مساره النهائي باستخدام `os.replace`.

## الخصوصية وحدود الأمان

الأداة لا تتصل بالإنترنت ولا تحتاج إلى حساب أو Token أو Telemetry أو ملف `.env`.

محتوى النسخ الاحتياطية **غير مشفر**. استخدام SHA-256 يكشف اختلاف البيانات عن البيان المخزن، لكنه لا يثبت صحة البيان نفسه إذا استطاع مهاجم تعديل البيانات والبيان معًا.

لذلك ينبغي حماية وسيط النسخ الاحتياطي بصلاحيات النظام، واستخدام تشفير القرص أو وحدة التخزين عند الحاجة.

راجع [SECURITY.md](SECURITY.md) للتفاصيل.

## الحدود الحالية

الإصدار الحالي يعتمد على نسخ كاملة، ولا يحتوي حاليًا على:

- نسخ incremental أو deduplication.
- ضغط.
- تشفير مدمج.
- نقل إلى التخزين السحابي أو البعيد.
- جدولة داخلية.
- حذف تلقائي حسب سياسة احتفاظ.
- واجهة رسومية.

إذا تغير ملف المصدر أثناء إنشاء اللقطة فقد يفشل التحقق، وعندها ينبغي إعادة العملية بعد توقف الكتابة على الملفات.
